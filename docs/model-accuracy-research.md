# Making SigSense accurate

Research checked: 2026-10-23. The intended scope is broad SDR signal identification. High accuracy must be demonstrated on independent captured signals; a generated-data score does not establish it.

## What is limiting this repository

The initial run used 1,024 training examples, 256 validation examples, and 32 labels, with no separate test set. It reached 23.4% best validation accuracy. That is a small baseline, not a production classifier.

Code inspection found conflicting supervision: the synthetic generator uses identical FSK logic for FSK/AIS/APRS, generic QPSK for several unrelated protocols, and the same OFDM logic for OFDM/WiFi/LTE/Zigbee. USB and LSB demo generation uses a single sinusoid; with a randomized carrier these become difficult to distinguish from a tone. Such examples cannot establish protocol recognition. The mixed source uses TorchSig for several of these protocols, but AIS/APRS/LTE/ACARS still had only local proxies. Existing synthetic prototypes were also used even for TorchSig-trained classes, creating a mismatch between classifier and library distributions.

Only magnitude spectrograms reach the model. Phase/constellation information is discarded. This is a particular limitation for higher-order modulation recognition. The application also classified one arbitrary middle window of a long capture, which may miss a burst. Neither more labels nor a larger image CNN fixes those input limitations.

The previous neighbor fallback treated a cosine similarity above 0.55 as classifier confidence and could override an unknown decision. That score had not been calibrated against out-of-distribution signals.

## Dataset shortlist

| [ORACLE, GENESYS](https://genesys-lab.org/oracle) | Captured IEEE 802.11a from 16 USRP transmitters; IQ + SigMF metadata | Additional receiver/channel domain for WiFi evaluation | Emitter IDs are not 16 protocol classes. Download selective parts first. Inspect packet annotations and isolate each capture group. Not downloaded. |

Independent test scenes should stay untouched. |

The shortlist intentionally distinguishes synthetic data, captured data, fingerprinting tasks, and wideband scenes. These sources are not interchangeable training sets. [SigMF](https://sigmf.org/) provides a useful sample/metadata interchange format; it is not itself a dataset.

## Class expansion implemented

The catalog grows from 32 to 48 labels while preserving the first 32 indices. New labels are ASK4, ASK8, ASK16, FSK4, FSK8, FSK16, GFSK4, GFSK8, MSK, GMSK, 16PSK, 32PSK, QAM32, QAM256, APSK16 and APSK32. All have explicit TorchSig mappings and local demo generators. Legacy ASK corresponds to the OOK generator; legacy FSK/GFSK now use binary variants rather than merging multiple orders. Chirp spread spectrum is no longer mislabeled FMCW.

Default generated-data training excludes AIS/APRS/LTE/ACARS pending verified data, yielding 44 trained labels for the mixed source. Those names remain in the catalog. Captured-data training can include any catalog class present in the supplied labels. Checkpoints store their own output labels, so an existing 32-class checkpoint remains loadable and a 44-class checkpoint cannot accidentally be decoded with the 48-class catalog indices. `/classes` distinguishes trained outputs from the complete catalog.

Next expansion should follow dataset availability: Panoradio's additional HF modes first, then packet-verified AIS/APRS/ACARS, LTE/5G NR, DAB/DVB, satellite telemetry, POCSAG/FLEX and radar subclasses as annotated IQ becomes available. These are proposed additions, not claims that the classifier recognizes them today. Keep protocol, modulation, signal family and emitter identity as separate annotations. A packet can be both WiFi and OFDM; it should not be forced into contradictory mutually exclusive annotations at every level.

## Recommended work, in order

1. **Define a measurable deployment target.** Proposed acceptance goals: at least 95% macro F1 on independent captured signals above 10 dB SNR, at least 90% recall for every supported priority class, and at most 1% false acceptance of unknown signals at a declared known-signal coverage. These are goals, not predicted results. Report uncertainty and SNR/sample-rate/receiver breakdowns. Low-SNR classes can be fundamentally ambiguous; permit unknown/family-only output.
2. **Build the capture benchmark before optimizing it.** Curate packet-verified bursts and noise/interference from multiple SDRs, transmitters, days, sites, gains and bandwidths. Split by collection session and transmitter/receiver combinations before cropping; reserve a location/device/day test set. Use thousands of independent bursts per priority class as a starting data budget and use learning curves to decide how much more is useful. Cropping a few recordings into millions of correlated windows is not equivalent.
3. **Retain raw complex IQ for uploaded/live captures.** Establish a 1-D residual CNN baseline, then compare a raw-IQ + multi-resolution spectrogram model against it under identical splits. [IQFormer's author implementation](https://github.com/WestdoorSad/IQFormer) is a relevant multimodal reference, not proof that a transformer will win on our data. Keep screenshot analysis as a separate model/task with realistic colormaps, cropping and display distortions.
4. **Generate diverse data and adapt to captures.** Apply carrier/phase offsets, sample-rate drift, multipath, IQ imbalance, gain variation, clipping and interferers in IQ before STFT, calibrated to the target receiver. TorchSig's [impairment design](https://events.gnuradio.org/event/26/contributions/752/attachments/220/586/TorchSig_GRCon2025.pdf) is a starting point. Generate fresh examples each epoch or store a large deduplicated corpus, rather than repeatedly training on a tiny fixed set. Fine-tune on diverse real recordings. Keep simulated and captured evaluation separate.
5. **Detect, channelize and aggregate bursts.** A spectrum scan needs a time/frequency detector, narrowband crops, appropriate resampling and multiple-window aggregation. Use sample rate, occupied bandwidth and center frequency as supporting context, and test that the model has not learned a frequency-band shortcut. Verify protocol hypotheses with preambles/sync words/CRC when possible; existing BLE decoding provides a useful starting point.
6. **Measure reliability and unknown rejection.** Temperature scaling can improve probability calibration ([original paper](https://arxiv.org/abs/1706.04599)); it does not make unknown rejection reliable. Tune rejection on a dedicated development set with unseen protocols/noise/interference, then measure false acceptance and coverage on a different unknown test set. Train and validate the embedding objective before using library similarity to accept enrolled classes. A similarity score is not a probability.
7. **Run controlled experiments.** Keep data/preprocessing/model versions, seed, splits and source licenses. Compare changes on validation, inspect confusion pairs, and evaluate the frozen winner once on the reserved test set. Use multiple training seeds before making a release claim. Do not compare the old 32-class validation percentage directly with a new 44-class test percentage.

## What changed now and what remains

Implemented: 48-label catalog, checkpoint-local label decoding, default proxy exclusions, deterministic TorchSig generation, separated synthetic split seeds, corrected RadioML split/mapping behavior, clean validation/test preprocessing, training-data-derived prototypes, cosine LR scheduling, early stopping by macro F1, validation-only temperature calibration, held-out test reports and a capture manifest loader that rejects recording/group split leakage. Library neighbors no longer override unknown using uncalibrated cosine similarity.

Not implemented yet: a raw-IQ encoder, streaming dataset generation, full IQ impairment curriculum, detection/channelization, protocol decoders beyond the existing BLE support, SNR-stratified reporting, captured benchmark acquisition, hierarchical classifier, or validated unknown-signal thresholds. Seven regression tests cover the implemented correctness changes. The expanded run is an engineering experiment on generated signals, not evidence of high real-world accuracy.

## Approved compact bundle follow-up

The user chose a compact download instead of the ~128 GB full-source proposal. The approved subset is exactly 2,468,806,272 bytes: RadioML 2016.10A (265,172,608), ITS band (388,327,096), and LTE/WiFi/DVB-T (1,815,306,568). These are the per-source HDF5 files from [RadioPile's publisher release](https://zenodo.org/records/22877108), not additional independent versions of RadioML. The larger seven-source bundle and Panoradio IQ remain unselected. The downloader defaults to the compact bundle, enforces a 3 GB cap, supports resume, and verifies publisher MD5/size before marking a file complete.

The compact loader additionally supports captured LTE and new capture-only labels 5G-NR, ITS-G5, C-V2X and DVB-T. Catalog size is now 52; the expected compact profile trains 49 labels. Local proxy AIS/APRS/LTE/ACARS examples are removed from this source mix, with LTE learned from the external datasets. Source HDF5 data are sampled per class and source before spectrogram materialization. Results are reported separately for RadioML, ITS, LTE/WiFi/DVB-T and generated signals. This helps expose capture-domain failures hidden by aggregate accuracy.

The initial expanded generated-only experiment finished 40 epochs in about 332 seconds and reached 35.2% held-out accuracy / 32.4% macro F1 over 44 classes. It remains a separate candidate under `checkpoints/expanded-44`; that score is not an over-the-air benchmark. The compact experiment uses a fresh seed and independent source/recording assignments.
